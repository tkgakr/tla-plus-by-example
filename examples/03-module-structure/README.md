# モジュールの構造

出典: [learning.tlapl.us / Introduction / Module Structure](https://learning.tlapl.us/intro/module-structure/)

本家ページのサンプルを、このリポジトリでそのまま実行できる日本語教材として再構成しています。
題材は、0 から 1 ずつ増える単純なカウンタです。

前のページ: [examples/02-tla-intuition](../02-tla-intuition)（TLA+ / TLC の直感）

---

## 1. TLA+ の仕様はモジュールに入れる

すべての TLA+ 仕様は、ヘッダとフッタで囲まれた**モジュール**として記述します。

```tla
---- MODULE MySpec ----
(* ここに仕様を書く *)
========================
```

実際に動かすファイルは [MySpec.tla](MySpec.tla) です。装飾の `-` や `=` は長くしても構いませんが、
どちらも 4 文字以上必要です。

---

## 2. ヘッダとファイル名

ヘッダは、4 個以上のハイフン、`MODULE`、モジュール名、4 個以上のハイフンの順です。

```tla
----------------------------- MODULE MySpec ----------------------------------
```

ここで最も大事なのは、**モジュール名とファイル名を一致させる**ことです。
`MODULE MySpec` と宣言したモジュールは `MySpec.tla` に保存します。一致しなければ、TLA+ ツールは
ファイル名とモジュール名が異なるというエラーを報告します。

ヘッダより前のテキストは TLA+ ツールに無視されます。[MySpec.tla](MySpec.tla) では、この領域に
仕様の概要を 2 行書いています。モデルの目的や前提を人間向けに残す場所として使えます。

> ヘッダより前なら構文解析されませんが、通常の説明にはコメントを使う方が、ヘッダを移動しても壊れにくく安全です。

---

## 3. フッタと変更履歴

フッタは 4 個以上の等号からなる行です。

```tla
========================
```

フッタより後のテキストも TLA+ ツールに無視されます。慣例として、仕様をいつ、なぜ変更したかという
変更履歴を置けます。`MySpec.tla` の末尾にある日本語の変更履歴はコメントではありませんが、フッタの後なので
構文エラーにはなりません。

無視される範囲は次のようになります。

```text
人間向けの説明             ← 無視される
---- MODULE MySpec ----    ← ここからモジュール
TLA+ の定義
========================   ← ここまでモジュール
変更履歴                   ← 無視される
```

---

## 4. `EXTENDS` で別のモジュールを利用する

`EXTENDS` は、別のモジュールで定義された演算子を現在のモジュールから使えるようにします。

```tla
EXTENDS Naturals, TLC
```

この例では、自然数の加算に `Naturals`、デバッグ出力の `PrintT` に `TLC` を使っています。

よく使う標準モジュールは次のとおりです。

| モジュール | 主な内容 |
| --- | --- |
| `Naturals` | 自然数と算術演算（`+`, `-`, `*`, `\div`, `%`） |
| `Integers` | 負の数を含む整数 |
| `Sequences` | 列と `Append`, `Head`, `Tail`, `Len` |
| `FiniteSets` | 有限集合と `Cardinality`, `IsFiniteSet` |
| `TLC` | `Print`, `PrintT`, `Assert` など TLC 固有の演算子 |

`EXTENDS` はファイル内容を文字列として貼り付ける命令ではなく、モジュールの定義を取り込むための宣言です。

---

## 5. 区切り線とコメント

モジュールの途中に 4 個以上のハイフンからなる区切り線を置けます。

```tla
----
\* 次状態関係
```

区切り線には意味がなく、長い仕様を読みやすく整理するためだけのものです。区切り線そのものには
ハイフン以外の見出しを書けないため、見出しは次の行のコメントにします。[MySpec.tla](MySpec.tla) では
「初期状態」「次状態関係」「検査する性質」の 3 区画に分けています。

サンプルには 2 種類のコメントも含めています。

```tla
(* 複数行にも使えるブロックコメント *)
\* 行末まで続く行コメント
```

区切り線と違い、コメントとして扱われるのは `(* ... *)` と `\* ...` の部分です。

---

## 6. `Print` と `PrintT` でデバッグ出力する

標準モジュール `TLC` には、モデル検査中の値を表示する演算子があります。

| 演算子 | 表示する値 | 式全体の値 |
| --- | --- | --- |
| `Print(value, expr)` | `value` | `expr` |
| `PrintT(value)` | `value` | `TRUE` |

`Print` は第 2 引数をそのまま返すので、式の途中に挿入できます。

```tla
Double(n) == 2 * Print(n, n)
```

`PrintT` は必ず `TRUE` を返すため、論理積 `/\` の 1 項としてアクションに追加できます。

```tla
Next ==
    /\ PrintT(<<"x is", x>>)
    /\ x' = x + 1
```

ここで表示している `x` は、遷移する**前**の状態の値です。タプル `<<"x is", x>>` は、たとえば
`<<"x is", 0>>` のように出力されます。

`Print` / `PrintT` はデバッグ用です。TLC は状態や遷移を探索する過程で式を評価するため、出力順を
システムの実行順とみなしたり、各行が一度だけ表示されると仮定したりしないでください。状態遷移を正確に追うには、
不変条件違反の反例トレースを使います。

## 7. TLC で実行する

`MySpec.tla` を開いて `Cmd + Shift + P` → **`TLA+: Check model with TLC`** を実行します。
同じディレクトリの [MySpec.cfg](MySpec.cfg) が設定ファイルです。

```cfg
INIT Init
NEXT Next
INVARIANT Bound
```

この仕様には `Spec == Init /\ [][Next]_x` がないため、前章と同じく `INIT` / `NEXT` を個別に指定しています。

CLI なら次のコマンドです。

```bash
cd examples/03-module-structure
java -cp "$(ls -d ~/.vscode/extensions/tlaplus.vscode-ide-*/tools/tla2tools.jar | tail -1)" \
  tlc2.TLC -workers 1 -config MySpec.cfg MySpec.tla
```

`Bound == x < 5` は「`x` は常に 5 未満」と主張します。しかし `Next` は `x` を無制限に増やすので、
TLC は `x = 5` で不変条件違反を見つけます。

```text
Error: Invariant Bound is violated.
...
State 6: <Next ... of module MySpec>
x = 5
```

これはサンプルの意図どおりの結果です。`PrintT` の出力と、`x = 0` から `x = 5` に至る反例トレースの
両方を確認してください。

## 8. 触って確かめる

- `MySpec.tla` を別名でコピーし、ヘッダの `MySpec` を変えずに実行する。名前の不一致エラーを確認できます。
- `EXTENDS Naturals, TLC` から `TLC` を外す。`PrintT` が未定義だという意味解析エラーになります。
- 区切り線を増減する。検査結果が変わらないことを確認できます。
- `Bound == x < 5` を `x < 3` にする。より短い反例トレースになります。
- `PrintT(...)` の行だけを削除する。表示は消えますが、到達状態と不変条件違反は変わりません。
- フッタの後に、TLA+ としては不正な日本語を追記する。それでも構文解析されないことを確認できます。
